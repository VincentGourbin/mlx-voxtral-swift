## Objectif
Un seul instrument qui passe par les chemins de la bibliothèque (piège 33), se valide en A/A, refuse un binaire Debug et une machine occupée (pgrep + manifestes `RuntimeBeacon` d'autres runtimes), et écrit une ligne JSON par mesure avec les révisions résolues, les phases, le pic MLX exact par phase (remise à zéro faite par l'instrument, plus par la bibliothèque) et le pic `phys_footprint`. Interface à livrer (reprise par toutes les fiches perf) : `VoxtralCLI bench stt --model <id> --backend mlx|auto --input <wav> [--language en|fr] [--max-tokens N]` · `bench tts --model <id> (--voice <preset> | --voice-embedding <f>) --text-file <f> --seed N [--streaming] [--warm-up]` · `bench realtime --model <id> --input <wav> [--delay 480]` · `bench enroll --model <id> --input <wav> --epochs N --seed N [--after-synthesis]` · `bench chat --model <id> --backend mlx|auto --input <wav> --questions docs/eval/chat-questions.json [--temperature T --top-p P]` (chemin `VoxtralPipeline.chat`, une ligne par question avec `ttft_ms` et tok/s ; ajouté par la critique de complétude du 2026-09-27 : sans lui, K-49 et K-70 n'ont aucune baseline) ; options communes `--passes N` (2) `--warmup N` (1, exclu) `--cooldown S` (120) `--tag A|B` `--out .local-runs/bench.noindex/` `--trace` (run de diagnostic séparé) ; sortie : une ligne `BENCH {json}` par passe, puis `AA …` si `--passes ≥ 2` ; `VOXTRAL_DTYPE_AUDIT=1` imprime les dtypes (mel, sortie encodeur, cache KV, logits).

**Porte** : A/A sur la même commande, deux passes après 120 s : dispersion ≤ 3 % sur le total hors chargement et sur `step_ms_p50`, pour `stt` (mini-3b-8bit, C-moyen EN, `.mlx`), `tts` (tts-4b-6bit, texte court, graine 42) et `realtime` (realtime-4b-4bit, C-moyen EN) ; `out_sha256` identique entre passes ; lignes JSON valides contre `docs/bench.schema.json` ; binaire Debug refusé (ligne `REFUSED debug build`) ; `grep -rn resetPeakMemory Sources/VoxtralCore` = 0 ; `chat` (mini-3b-8bit, C-court EN, question fixe de `docs/eval/chat-questions.json`, greedy) : dispersion ≤ 3 % sur `ttft_ms` et tok/s.

Si l'A/A dépasse 3 % : ne pas enregistrer de baseline ; chercher la source de bruit (piège 8, 11, 19), refaire, sinon `blocked`.
