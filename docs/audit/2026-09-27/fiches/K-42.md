## Objectif
Choisir le backend par défaut et la précision d'encodeur par une matrice mesurée : encodeur {Core ML `.cpuAndGPU`, `.cpuAndNeuralEngine`, `.all`, MLX 6 b, 8 b, bf16} × LM {4 b, 8 b} sur Mini, temps par fenêtre et de bout en bout, mise en place à froid (téléchargement et compilation séparés), WER, et parité Core ML/MLX des embeddings.

**Porte** : règle : Core ML reste le défaut `.auto` seulement s'il est ≥ 1,2× plus rapide **et** WER ≤ +0,3 pt **et** parité (L2 relative des embeddings ≤ 1e-2, transcriptions greedy identiques sur 5 fichiers), sinon `.mlx` par défaut (ASK-6) ; chaque cellule a une ligne `BENCHMARKS.md` ; pour chaque largeur, le pack retenu a un WER ≤ bf16 + 0,3 pt ; décision écrite dans `docs/knowledge/decisions/reference-profiles.md` ; si Core ML est gardé : reconversion `convert.sh` (K-19) rejouée de bout en bout.

Si la porte n'est pas atteinte : le code est retiré, la fiche passe « retirée » avec la mesure (un rejet documenté vaut une technique retenue).
