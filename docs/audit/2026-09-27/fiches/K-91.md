## Objectif
Le chargeur Realtime lit le format voxmlx (« Format C ») : config au format `params.json` avec `quantization`, clés
`adapter.w_in.*`, `encoder.layers.N.attention.q_proj.*`, `language_model.layers.N.*`. Tout pack dont les clés ne
couvrent pas les paramètres du modèle est refusé par une erreur typée (aujourd'hui : poids aléatoires, sans erreur).
Les deux packs existants sont référencés (pas republiés) et deviennent chargeables pour K-78.

**Porte** :
- format voxmlx détecté (config au format `params.json` avec `quantization` ; clés `adapter.w_in.*`, `encoder.layers.N.attention.q_proj.*`, `language_model.layers.N.*`), clés mises en correspondance avec les noms internes, quantification lue depuis `params.json` ; `mlx-community/Voxtral-Mini-4B-Realtime-6bit` (3 609 304 614 o) et `ellamind/Voxtral-Mini-4B-Realtime-8bit-mlx` (4 714 618 595 o) chargés avec 0 paramètre non couvert et 0 clé en trop, révisions et SHA-256 épinglés (référencés, pas republiés : ASK-16, ASK-22), entrées de registre additives ; refus explicite : un pack dont les clés ne couvrent pas tous les paramètres du modèle lève une erreur typée nommant le format détecté et les premières clés manquantes (test rouge avant : aujourd'hui, un pack voxmlx se charge en poids aléatoires sans erreur ; fixtures « voxmlx tronqué » et « format inconnu ») ; qualité (`voxtral eval realtime`, K-33) : WER C-moyen EN/FR 8 bits ≤ 4 bits + 0,2 pt et 6 bits ≤ 4 bits + 0,5 pt (réf. 1,05 / 1,97 %, `EVAL-realtime-4b-4bit` l. 289 ; ASK-11) ; une ligne `bench realtime` C-moyen EN par pack (`step_ms_p50`, pic), la matrice restant à K-78.

Si la porte qualité n'est pas atteinte : le refus explicite est livré seul (il ne dépend pas de la lecture) ; la lecture
voxmlx est retirée et documentée, les entrées de registre ne sont pas ajoutées.
