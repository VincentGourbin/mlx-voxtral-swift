## Objectif
Un champ additif pose `Memory.cacheLimit` après le chargement selon le profil (fast : quelques Go ; lean : `min(1 Go, max(256 Mo, dispo/6))` et `memoryLimit = dispo − 2 Go`), restaure la valeur précédente à `unload()`, et les 3 pipelines vident le cache en fin de réponse (lean) et dans `unload()` ; le vidage aveugle Realtime tous les 256 pas est gardé ou retiré selon la mesure.

**Porte** : STT à 10 min d'audio : pic `phys_footprint` ≤ pic actif MLX + `cacheLimit` + empreinte Core ML (+5 %) ; temps fast ±5 % ; TTS : après `unload()`, footprint ≤ référence du process + 200 Mo, lean ≤ +5 % de temps pour un pic −20 % au moins sur le texte long ; Realtime : après `unload()`, footprint = avant chargement ±200 Mo, `step_ms_p50` ±3 %, max/médiane des pas ≤ 1,3.

Si la porte n'est pas atteinte : le code est retiré, la fiche passe « retirée » avec la mesure (un rejet documenté vaut une technique retenue).
