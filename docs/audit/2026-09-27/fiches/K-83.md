# K-83 — `voxtral eval chat` : compréhension audio mesurée (questions à faits attendus, EN/FR)

- **Source** : question de Vincent du 2026-10-05 (« des tests de compréhension des audios, pas que du transcribe ? ») ; K-34 ne mesure que le temps du chat (4 questions, `bench chat`), jamais la justesse des réponses
- **Prérequis** : K-33 (corpus, empreintes), K-34 (baseline chat) · **⛔ GATE** : non
- **Effort** : M · **Risque API publique** : aucun (outil CLI)
- **Cible** : `macos-gpu` · **Lot** : 4 · **Branche** : `claude/action-plan-skills-beta-wifgmu`
- **ASK liées** : aucune

## Objectif
Un outil reproductible qui note la compréhension audio (mode chat) des modèles STT : pour chaque clip à texte exact
(C-moyen EN/FR, 20 s EN/FR), des questions fermées dont la réponse attendue est un ensemble de faits (mots ou
nombres présents dans la référence), notées automatiquement (fait présent dans la réponse normalisée, comme le WER
de K-33) ; génération déterministe (greedy).

**Porte** : `docs/eval/chat.json` versionné (questions, faits attendus, SHA-256 des clips ; ≥ 6 questions par clip,
EN et FR) ; `$CLI eval chat --model <m> --backend mlx` émet une ligne `EVAL {"pipeline":"chat",…,"facts_found",
"facts_total","score"}` par question et une ligne de synthèse par clip ; deux exécutions donnent des `out_sha256`
identiques ; une ligne `BENCHMARKS.md` par modèle ∈ {mini-3b-4bit, mini-3b-8bit, mini-3b, small-4bit} (`.mlx`) ;
score de référence consigné dans `docs/knowledge/benchmarks/` (porte des fiches qui toucheront au chemin chat).

## Étapes
1. Questions et faits : rédigés depuis `docs/eval/refs/*.txt` uniquement (le fait doit être dans la référence) ;
   aucune question dont la réponse dépend d'une traduction.
2. `EvalChat` dans `EvalCommand.swift` (réutilise `EvalCorpus.load`, `WER.normalize`, `BenchJSON.emit`).
3. Contrôle de l'outil sans GPU : réponses factices (une juste, une fausse, une partielle) → scores attendus
   (script `Scripts/check-eval-chat.sh`, comme `check-wer.sh`).
4. Mesure : machine-check avant chaque modèle ; 2 exécutions par modèle (déterminisme).
5. Journal (PLAN.md §7, docs/knowledge/log.md), commit `feat(K-83): …`, rapport.

## Pièges
- Une question ouverte (« résume ») ne se note pas par faits : hors outil (reste dans `bench chat`, temps seulement).
- FR : Mini peut répondre en anglais ; noter la langue de la réponse, ne pas compter un fait traduit comme présent.
